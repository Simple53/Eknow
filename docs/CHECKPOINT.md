# 实施检查点

视觉基准：第 3 稿；修订稿在 `docs/design/04-family-journal.png`。统一纸白 / 墨黑 / 靛蓝，底部五个图标无可见文字；使用可访问名称与选中指示。页面只留操作文案，不设解释板块用途的副标题。

构建次序：成员隔离和数据规则 → 衣橱与市场 → 自由/AI 搭配 → 家庭人体档案 → 视频 → 日历导出 → 两端验证。每个成员独立持有单品、搭配、穿着记录和人体档案。设备内家庭档案不是登录或访问控制。

服务边界：市场外链可直接使用；内嵌结果需要授权供应商。AI 必须返回本成员实际拥有的 ID，不能用本地规则冒称模型。相机、视频播放与生成任务分开命名。量体照片不提交 Git、默认不上云；尺码范围不是人的实测数据。

## 已落地

| 模块 | 已实现 | 尚未证明或未交付 |
| --- | --- | --- |
| 网页 / App | React + HeroUI 与 Expo + HeroUI Native；统一图标、五个底栏入口、二级设置；IndexedDB / SQLite 本机保存 | 未做账户同步；同设备家人不是权限隔离账户 |

| 搭配 | 上下装独立切换、按当前成员衣物推荐、场景和手填天气、记穿与成本 | 未配置真实模型进行计费测试；暂无自动天气定位 |
| 体型 | 家庭成员切换、手填、三视角轮廓与已知身高校准、逐项确认、区分品牌参考和实测 | 无校准过的精度指标；不等于精密扫描或完整 3D 人体重建 |
| 试穿 | 透明服装叠加二维人物；Web 相机预览和本地视频，原生系统拍摄及视频播放 | 未接实时生成视频、AR 遮挡或布料仿真 |
| 日历 | 按本地日期记穿/补记、撤销、同日多套和去重成本；导出 PNG | 原生导出与相机需真机核验 |

## 检查与续做

1. 领域与服务适配器测试覆盖：成员隔离、同日成本、异常轮廓、授权缺失、模型白名单、商品币种与链接解析。单独的 React 组件测试从空衣橱添加上下装、记穿、持久化、切换家人再重新挂载；不使用个人数据。
2. 在 `apps/web` 运行 `npm run test:flow`、`npm run build`、`npm run test:sites`；在 `apps/mobile` 运行 `npm run typecheck` 和双平台 Expo export。目前只有 JS 资源包验证，不是已签名的安装包。
3. 下一步需要设备/授权：在 Android、iOS 真机验证系统权限、拒绝授权、量体输入、分享与恢复；用测试账号跑真实供应商；有授权且有代表性的样本后再评估量体误差。不把缺少这些条件视作联调通过。
